# Касса Kemal Usman

Продажи с телефона для двух магазинов Kemal Usman Parfume — как «Касса Smarket» у Smart Centr, но **отдельно**:
свой сервер, своя база, свой ключ 1С. С кодом, серверами и ключами Smart Centr ничего общего нет.

```
телефон продавца ──► сервер кассы (kassa.kemalusman.kg) ◄── программа кассы на ПК магазина ──► 1С Kemal Usman
   PIN, продажа          база SQLite, правила                 товары и остатки → сервер
   «Сегодня», остаток                                         продажи → Реализация + ПКО в 1С
```

## Что умеет (этап 1)

- Вход по PIN (4–6 цифр, у каждого свой). PIN владельца задаётся на ПК магазина, сотрудников заводит владелец в кассе.
- Продажа: магазин (Kemal Usman / Osh), товары в **мл** (с дробью: 2,5 мл) или **шт**, цена за 1 мл / 1 шт
  (подставляется розничная цена магазина из 1С, можно поменять), оплата **наличные**, **перевод** или **две части**.
- Остаток по каждому магазину; продажа больше остатка не проходит (учитываются и ещё не проведённые продажи).
- «Сегодня»: итоги по магазинам (наличные / перевод), список продаж, чек для печати, отмена.
- Отмена: не проведённая — сразу; проведённая — программа на ПК распроводит документы в 1С и помечает их на удаление.
- Сотрудник может быть привязан к своему магазину — тогда продаёт только там.

В 1С каждая продажа — «Реализация товаров и услуг» (партнёр «Клиент розничная», соглашение «Розница <магазин>», склад
магазина, время продажи) и «Приходный кассовый ордер»: касса «Касса <магазин>» за наличные, «Перевод <магазин>» за перевод.
В комментарии — метка `КАССА:<номер операции>`, продавец, покупатель.

## Папки

| Папка | Что там |
|---|---|
| `server/kassa_server/app.py` | сервер (FastAPI): адреса для телефона и для программы 1С |
| `server/kassa_server/rules.py` | правила: продажа, остаток, оплата, PIN, чек — с проверками в `server/tests` |
| `server/kassa_server/page.html` | страница для телефона (один файл, без сборки) |
| `agent/kassa_agent.py` | программа на ПК магазина: связь сервера и 1С |
| `agent/onec_kemal.py` | что программа читает из 1С и какие документы создаёт |
| `agent/install-agent.ps1` | задача Windows «Kemal касса» (запуск при входе в Windows) |

## Выкладка (этап 4, делает владелец)

Всё — из папки `kemal-usman` после `git pull` (касса должна быть в `main`):

1. Cloudflare → DNS: запись `kassa` → туннель `parfum` (CNAME на `<id туннеля>.cfargotunnel.com`, облако оранжевое) — сделано 23.10.
   Домены Kemal идут через Cloudflare Tunnel, настроенный файлом на сервере: скрипт сам добавит `kassa` → `localhost:8095` в его настройки.
2. `bash kassa/deploy/deploy-kassa.sh check` — только посмотреть сервер (можно пропустить).
3. `bash kassa/deploy/deploy-kassa.sh` — касса на сервер: служба `kemal-kassa` (127.0.0.1:8095, не Docker), секреты в
   `/root/kemal-kassa/.env`, ключ клуба в `pb_data/kassa_credentials.json`, адрес в nginx (или Caddy, если стоит он), секрет 1С → `kassa/agent/agent.env`.
4. `./deploy-odengi.sh` — обычная выкладка сайта; заодно ставит `pb_hooks/kassa.pb.js` (бонусы, наличие на сайте). Потом Cloudflare → Purge Everything.
5. На ПК магазина: вписать в `kassa/agent/agent.env` пользователя и пароль 1С Kemal (`ONEC_USER`, `ONEC_PASSWORD`), затем
   `python kassa/agent/kassa_agent.py setup --apply` (кассы «Перевод <магазин>» в 1С), `python kassa/agent/kassa_agent.py owner-pin`,
   `powershell -ExecutionPolicy Bypass -File kassa/agent/install-agent.ps1` (задача Windows «Kemal касса»).
6. Телефон: `https://kassa.kemalusman.kg/kassa/` → PIN владельца → «Сотрудники» → продавцы; «Остаток» → «Сайт ↔ 1С».

## Этапы

1. ✅ Сервер + страница + программа 1С: PIN, продажа (мл/шт, 2 магазина, нал/перевод), остаток, «Сегодня», отмена, сотрудники.
2. ✅ Продажа «В долг» (до даты или рассрочка 2–12 мес., сколько заплатил сейчас; покупатель по телефону находится или
   заводится в 1С), вкладка «Оплата» (долги из 1С, оплата → ПКО по реализации; старые долги из Billz — первичные документы ввода остатков,
   оплата → ПКО по тому же объекту расчётов), владельцу: деньги в кассах, «Расход» по статье
   (РКО со статьёй), «Перевод» между кассами (РКО + ПКО), прибыль за сегодня / 7 / 30 дней, общий капитал, рейтинг продавцов
   и бонус (% от прибыли, у каждого свой). Не сделано: ценники — нужен ответ, какой принтер в магазине.
3. ✅ Бонусы клуба Kemal: по телефону покупателя касса показывает баланс, списывает до 30 % суммы (настройка useBonusPercent
   сайта), после проведения в 1С начисляет bonusPercent % от оплаты, отмена всё возвращает. Хранятся там же, где у сайта
   (PocketBase clients.bonus_balance), через обработчик `pb_hooks/kassa.pb.js` (ключ — `pb_data/kassa_credentials.json`).
   В 1С бонусы — ручная скидка строк реализации. Чек в WhatsApp (Green API Kemal): кнопкой, а для долга и оплаты долга — сам.
   Онлайн договор для долга и рассрочки: ссылка в чеке, покупатель открывает и нажимает «Согласен» (время, адрес, телефон
   записываются; текст договора — черновик, владельцу проверить).
3а. ✅ Сайт ↔ 1С, только наличие (владелец выбрал вариант 2): владелец в «Остаток» → «Сайт ↔ 1С» связывает товар сайта с товаром
   1С (точные совпадения — одной кнопкой, остальные — по подсказке), после каждого обмена с 1С касса ставит на сайте галочку
   «в наличии» у вариантов «N мл» по остатку (у «Упаковки» — если указан флакон-шт). Цены и описания на сайте не меняются,
   несвязанные товары не трогаются. На сайт пишет `pb_hooks/kassa.pb.js` (/api/custom/kassa/stock). Магазины для сайта —
   `KASSA_SITE_SHOPS` (по умолчанию оба).
4. Выкладка (делает владелец): DNS `kassa.kemalusman.kg`, docker на сервере, секрет, программа на ПК магазина.
