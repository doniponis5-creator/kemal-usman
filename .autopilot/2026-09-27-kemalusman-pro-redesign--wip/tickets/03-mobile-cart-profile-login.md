## Что должно заработать

Все остальные экраны покупателя — вход, регистрация, корзина, оформление (доставка/самовывоз,
оплата), чек, успех, «Мои заказы» (с миниатюрами и «Заказать снова»), профиль, бонусы,
рефералы, уведомления, профиль гостя — в той же системе, что каталог. Экран входа сохраняет
тёмное фото Кемаля как момент бренда, но поля и кнопки — в новой системе. Плюс исправления
админки, которые живут в `App.jsx`: запуск админки больше не затирает серверные настройки и
баннеры, «Уведомления» открываются на телефоне, одно окно входа админа, выход на десктопе
удаляет токен.

## Критерии приёмки

- [ ] Вход, регистрация, корзина, оформление, окно O!Деньги, чек, успех, заказы, профиль, бонусы, рефералы, уведомления — только токены, без системных неоновых цветов, без эмодзи (иконки одного набора); статусы заказа приглушёнными статус-токенами
- [ ] Липкие шапки корзины/заказов/профиля не заезжают под статус-бар; тап-зоны ≥ 44pt («Назад», количество, «×», «Изменить»); KG без жёсткого русского
- [ ] Профиль гостя: без фейкового реферального кода, с призывом зарегистрироваться; «Мои заказы»: миниатюры товаров; «Заказать снова» кладёт доступные позиции в корзину
- [ ] Имя бренда в интерфейсных текстах — только «Kemal Usman»
- [ ] A-01/A-02: админка не отправляет настройки/баннеры на сервер до загрузки с сервера и без действия админа; сохраняются только изменённые поля
- [ ] A-11, A-45, B-04: «Уведомления» открываются на телефоне; одно окно входа админа; «Выход» (включая десктоп) удаляет токен админа
- [ ] Оформление заказа наличными, бонусы и рефералы работают как раньше (логика не тронута); `npm run build`, `npm run lint` без новых ошибок; сценарий «каталог → корзина → оформление (без отправки) → профиль» пройден в симуляторе
